# 数据与发布责任矩阵

本矩阵用角色先固定责任边界；姓名、团队和 GitHub handle 需要在接入实际协作组织后填写。

| 角色 | 责任 | 当前指派 |
| --- | --- | --- |
| Safety Gate 数据负责人 | 审阅每周公开快照 PR、核对 alert ID / URL / 日期 / 措施 | 待指定 |
| 产品安全负责人 | 复核风险、召回、下架 / 撤回分类和产品匹配 | 待指定 |
| CRA 证据负责人 | 维护 `craReviewRecords`，确认报告节点、监管措施和整改期限 | 待指定 |
| CRA / 法务合规负责人 | 确认双轨边界、免责声明和外部发布范围 | 待指定 |
| 发布负责人 | 执行 `npm run release:check`，合并刷新 PR，保留回滚能力 | 待指定 |

## 最低审阅规则

- Safety Gate 刷新 PR 至少由 Safety Gate 数据负责人和产品安全负责人审阅。
- CRA 清单变更至少由 CRA 证据负责人和 CRA / 法务合规负责人审阅。
- 同一个人不应同时创建并最终批准自己的 CRA 产品级证据变更。
- 任何来源不明、产品匹配不确定或状态含义不清的记录，保持在 PR 中，不进入运行时。

## 交接信息

请把每个角色的姓名 / 团队 / GitHub handle 填入本文件，并同步到仓库的 PR 审阅规则。没有实际人员信息时，系统保持技术可发布，但不视为完成业务签核。
